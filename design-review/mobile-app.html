Mobile app – one design, two native feels

The same screens, content and colours as the desktop redesign, rebuilt for a phone: thumb-reach navigation at the bottom, one task per screen, 44–52px touch targets, 15–16px text, and each platform's own chrome (iOS tab bar + large titles + back swipe; Android bottom navigation + top app bar + gesture bar). All data below is placeholder.

1Bottom navigation, per role. Lead: Home · Pipeline · Inbox · Capacity · More. Editor: My queue · Inbox · Brand kits · More. QC: Queue · Inbox · Brand kits · More. HR: Directory · Inbox · More. The 14-link desktop sidebar disappears.
2Cards instead of tables. Every table becomes a card list; the deadline is the loudest thing on a card; filters live in a bottom sheet behind one button, status in a scrollable chip row.
3Native behaviours. Safe-area insets (notch, home bar), pull-to-refresh, swipe-back (iOS) / system back (Android), bottom sheets with a grabber, haptic-friendly 44pt targets, no hover-only UI, dark mode follows the OS.
4Installable. Delivered as an installable web app (home-screen icon, full-screen, splash, push alerts) from the same React code, with a Capacitor wrapper if you want App Store / Play Store listings. See "How it's built".

How it's built

ASame React app. Below 768px a MobileShell replaces the sidebar: top bar + bottom tab bar chosen per role, content in one scrolling column. Desktop is untouched.
BPWA: manifest.webmanifest, icons, viewport-fit=cover, theme-color, Apple meta tags, the existing service worker for push. iPhone: Share → Add to Home Screen (push needs iOS 16.4+ and the installed app).
CStore apps (optional): wrap the same build with Capacitor for App Store / Google Play, adding native push, biometrics and haptics. This is a separate, later step.
DPlatform feel: detect iOS vs Android once and switch the chrome (large title + tab bar vs app bar + nav bar + FAB); everything inside the content area is shared.
